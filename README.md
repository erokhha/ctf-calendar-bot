# CTF-календарь — учебный проект Ерохиной

Единая учебная адаптация `Wyndace/CTF-Calendar-BOT` для практических работ по Telegram Bot API. Базовый сценарий — просмотр ближайших CTF-соревнований и переключение их карточек. К нему добавлены команды, reply-клавиатура, JSON API, картинки, геолокация, SQLite, обработка ошибок и логирование.

Исходный CTF-проект и объём переработки указаны в [PROVENANCE.md](PROVENANCE.md). Проект с таро не использовался. Автоматический `Timer` исходника не переносился: в этой версии просмотр CTF работает по запросу, а учебная рассылка запускается отдельной CLI-командой.

## Что реализовано и проверено

| Действие | Результат |
| --- | --- |
| `/start` | Персональное приветствие, главное меню |
| `/help`, «Помощь» | Справка по функциям |
| `/id`, `/myid`, «Мой ID» | ID пользователя и ID чата |
| «Фото котика» | Запрос TheCatAPI: случайное изображение породы `beng` |
| «Мой аватар» | Робот RoboHash, `set=set1`, фон `bgset=bg1` |
| `/weather`, «Погода» | Кнопка `request_location=True`; получение текущей погоды |
| «Погода в Москве» | Явно выбранный запасной город, без выдачи Москвы за геолокацию пользователя |
| `/ctf`, `/showctf`, «CTF-соревнования» | JSON CTFtime, ближайшие события, inline-переключение |
| Неизвестная команда/текст | Понятное сообщение и возврат меню |
| `api_examples.py` | Прямые `getUpdates`, `sendMessage`, `sendPhoto`, рассылка известным личным чатам |

Локально выполнены 44 автоматические проверки. Обработчики использовали два синтетических пользователя, JSON API обслуживал реальный локальный HTTP-сервер, а исходящие методы Telegram были заменены `AsyncMock`. Отдельно исполнены сценарии двух фикстур и упражнение по уровням логирования. Данные и фактические результаты находятся в `evidence/`.

**Реальная регистрация BotFather, запуск с токеном, отправка сообщений живым пользователям, проверка внешних API и размещение на PythonAnywhere не выполнялись.** Это требует аккаунта и ключей владельца. Тестовые картинки — только URL в зафиксированном вызове `sendPhoto`; доставка и визуальный вид изображения этими тестами не подтверждаются. Список действий для завершения — [MANUAL_CHECKLIST.md](MANUAL_CHECKLIST.md).

### Установка

Откройте терминал в корне проекта. Python 3.12 рекомендован, чтобы воспроизвести проверенное окружение.

```bash
python -m venv .venv
```

macOS / Linux / Bash:

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните `.env` в редакторе:

```dotenv
TELEGRAM_BOT_TOKEN=
WEATHER_API_KEY=
CAT_API_KEY=
CAT_BREED=beng
```

- `TELEGRAM_BOT_TOKEN` — токен зарегистрированного бота от BotFather. Без него `main.py` останавливается до сетевого запроса.
- `WEATHER_API_KEY` — ключ OpenWeatherMap Current Weather. Без ключа остальные функции работают, погода показывает контролируемое сообщение о недоступности.
- `CAT_API_KEY` — ключ TheCatAPI. Заголовок `x-api-key` передаётся, если ключ заполнен. Доступ к фильтрации пород и ограничения API необходимо проверить с актуальным аккаунтом; при HTTP 401/403 владелец проверяет ключ и доступ.
- `CAT_BREED=beng` — бенгальская порода. Для другой породы нужен её код из TheCatAPI.

Реальные ключи не входят в исходники, журнал или отчёт. `.env`, `.venv`, рабочая БД и runtime-логи исключены в `.gitignore`. В `.env.example` нет действующих ключей. Для совместимости с методичкой также читаются `TOKEN` и `TOKEN_WEATHER`, если основные имена переменных отсутствуют.

## Запуск

```bash
python main.py
```

Откройте зарегистрированного бота в Telegram и отправьте `/start`. Остановить процесс — `Ctrl+C`. При старте автоматически регистрируются подсказки команд. HTTP-сессия создаётся в `post_init` и закрывается в `post_shutdown`.

Только один polling-процесс должен получать обновления данного токена. Не запускайте одновременно `main.py` и CLI `get-updates`. В текущей реализации webhook не используется; при переходе с webhook его нужно отключить через настройки Bot API до polling.

### Параметры внешних API

| Сервис | Адрес и параметры | Используемые поля |
| --- | --- | --- |
| TheCatAPI | `GET https://api.thecatapi.com/v1/images/search` — `limit=1`, `breed_ids=beng`, `order=RAND`, `mime_types=jpg,png`, `has_breeds=1` | `data[0].url`; запрос требует JSON-массив с непустым HTTPS URL |
| RoboHash | `https://robohash.org/<sha256>.png?set=set1&bgset=bg1&size=400x400` | Готовое изображение по URL |
| OpenWeatherMap Current Weather | `GET https://api.openweathermap.org/data/2.5/weather` — `lat`, `lon`, `appid`, `units=metric`, `lang=ru` | `name`, `weather[0].description`, `main.temp`, `main.feels_like`, `wind.speed` |
| CTFtime | `GET https://ctftime.org/api/v1/events/` — `limit=10`, `start=<Unix UTC>`, `finish=<Unix UTC + 90 дней>` | `id`, `title`, `format`, `start`, `finish`, `onsite`, `location` |

Сервис погоды в этой реализации называется **Current Weather**: в тексте методички упомянут One Call 3.0, но приведён код именно `/data/2.5/weather`. В проекте использован этот фактический endpoint.

У CTFtime даты запроса рассчитываются при каждом открытии списка; фиксированный 2021 год удалён. Даты карточек преобразуются в UTC+3 и подписаны как московское время. Кнопки переключают личный снимок списка, поэтому нажатие не меняет привязку индекса к событию при обновлении внешних данных. В памяти сохраняются последние пять списков на пользователя; после перезапуска старые кнопки предлагают заново открыть `/ctf`.

В RoboHash используется строка `ctf-student-v1|id=<user_id>|name=<username или first_name>`, затем SHA-256. При неизменных ID и имени URL одинаков; у разных пользователей — различается. Смена имени меняет аватар. ID и имя не отправляются генератору открытым текстом. Это пользовательский генератор аватара, а не получение фотографии профиля Telegram.

## Прямой Bot API и учебная рассылка

Сначала остановите `main.py`, попросите участников написать боту `/start`, затем:

```bash
python api_examples.py get-updates
```

Команда делает HTTP GET, разбирает `result`, запоминает только личные чаты в SQLite и показывает следующий возможный `offset`. Чтобы подтверждать уже прочитанные обновления и не получать их повторно, в следующем ручном запросе можно явно указать полученный `--offset`. При первом запросе без offset очередь не сбрасывается.

В следующих примерах замените `123456789` на ID из собственного вывода `get-updates`, а URL — на доступное изображение:

```bash
python api_examples.py send-message 123456789 "Привет! Учебная проверка Bot API."
python api_examples.py send-photo 123456789 "https://robohash.org/ctf-calendar-practice.png?set=set1&bgset=bg1"
```

Для рассылки приветствия и изображения **всем известным активным личным чатам**:

```bash
python api_examples.py broadcast --photo-url "https://robohash.org/ctf-calendar-practice.png?set=set1&bgset=bg1" --confirm
```

Без `--confirm` программа завершается до чтения токена и до сетевого запроса. Рассылка не запускается автоматически ботом и не воспроизводится при импорте модуля. Список получателей ограничен уже начавшими диалог личными чатами; новые адресаты из произвольного списка не добавляются. Если пользователь заблокировал бота, HTTP 403 деактивирует его запись, а отправка остальным продолжается. HTTP 429 с `retry_after` до 30 секунд повторяется один раз. В остальных случаях записывается неудачный результат без автоматического бесконечного повтора. Результат отражает, успел ли отправиться только текст или текст и изображение.

Внутри CLI отправка использует POST. Для сопоставления с браузерным упражнением в методичке шаблоны запросов имеют вид:

```text
https://api.telegram.org/bot<TOKEN>/getUpdates
https://api.telegram.org/bot<TOKEN>/sendMessage?chat_id=<CHAT_ID>&text=<URL_ENCODED_TEXT>
https://api.telegram.org/bot<TOKEN>/sendPhoto?chat_id=<CHAT_ID>&photo=<URL_ENCODED_PHOTO_URL>
```

`<TOKEN>`, `<CHAT_ID>` и текстовые значения — заполнители, это не действующие ссылки. Если выполняется браузерное упражнение, токен необходимо закрыть на снимке экрана и не включать его в публикуемый отчёт.

## Локальная проверка без ключей

```bash
python run_local_checks.py
python demo_local.py
python example_for_log.py
```

Ни одна из этих команд не отправляет сообщения в Telegram. Первая команда исполняет `unittest` и сохраняет `evidence/test_output.txt` и `evidence/test_results.json`. Вторая выполняет реальные обработчики, записывает фактические ответы и HTTP-запросы к localhost в `evidence/local_transcript.json` и `.txt`. Третья показывает пороги логирования WARNING, INFO и DEBUG, одновременно пишет три отдельных log-файла.

Проверены успех и отказы JSON API: пустой список и URL, некорректная ссылка, HTTP 401/403/429/500, недоступный сервер, тайм-аут, HTML вместо JSON, повреждённый JSON, неполная схема, неверные координаты, отсутствующий обязательный токен и ключ погоды. Проверены команды, персонализация, параметры API, возврат клавиатуры после погоды, явная Москва, CTF snapshot/callback, импорт без polling, жизненный цикл сессии, redaction секретов и продолжение рассылки после отказа одного адресата.

Тест сборки приложения проверяет регистрацию типов обработчиков без сетевого соединения. Он изолирует переменные прокси хост-машины; это не проверка SOCKS или хостинга. Рабочая схема маршрутизации также видна в `bot.py`: команды зарегистрированы раньше общего текста, а фильтр общего текста исключает `filters.COMMAND`.

## Логи и диагностика

Основной лог — `logs/bot.log`, формат: время, уровень, модуль, событие. Та же запись выводится в консоль. Уровень по умолчанию — INFO; `LOG_LEVEL=DEBUG` включает подробные сообщения. Файл ограничен 1 МБ, сохраняются два резервных файла. Сообщения и геолокация пользователей не записываются в журнал.

| Код в журнале | Что проверяет владелец |
| --- | --- |
| `missing_key` | Заполнен ли `WEATHER_API_KEY` в .env |
| `unauthorized` | Ключ, доступ аккаунта к API, ограничения сервиса/прокси |
| `rate_limit` | Лимит запросов; повторить позднее |
| `timeout`, `network` | Интернет, DNS, proxy и доступность endpoint |
| `invalid_json`, `invalid_schema` | Соответствие ответа ожидаемой JSON-схеме |
| `invalid_url`, `empty` | Сервис не вернул подходящую фотографию |
| `telegram_update_failed type=Forbidden` | Пользователь заблокировал бота; запись чата деактивируется |

## Развёртывание на PythonAnywhere

Ниже инструкция для владельца аккаунта. Факт выполнения деплоя не заявляется.

1. Создайте аккаунт PythonAnywhere и подтвердите почту. Во вкладке Files загрузите проект в отдельную папку, например `ctf_calendar`. Виртуальное окружение с другого компьютера не загружайте.
2. Откройте Bash console, перейдите в папку и создайте окружение:

```bash
cd ~/ctf_calendar
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

3. Заполните `.env` своими ключами. Если доступная версия Python отличается, выберите её явно и проверьте совместимость зависимостей локальными тестами.
4. Внешние запросы бесплатного аккаунта ограничены списком разрешённых доменов. Проверьте доступность `api.telegram.org`, `api.openweathermap.org`, `api.thecatapi.com`, `ctftime.org`; отдельно проверьте, что Telegram может загрузить URL изображений. Актуальный список: https://www.pythonanywhere.com/whitelist/.
5. PythonAnywhere использует HTTP-прокси. `aiohttp.ClientSession(trust_env=True)` и HTTPX настроены на системные переменные окружения. При необходимости можно явно установить `TELEGRAM_PROXY_URL=http://proxy.server:3128`. Это настройка окружения, а не строка, которую нужно безусловно вшивать в исходник.
6. Выполните `python run_local_checks.py`, затем `python main.py`, откройте бота и пройдите ручной чек-лист. Снимите результат Telegram и вывод консоли без секретов.
7. Проверьте `logs/bot.log` при ошибках. Консольный процесс бесплатного аккаунта может быть остановлен или перезапущен сервисом; работа 24/7 этим способом не гарантируется. Для постоянного процесса используйте доступный подходящий тариф с Always-on task либо собственный сервер.

Проект рассчитан на прямое соединение или HTTP(S)-прокси. Если в вашей среде задан **SOCKS** в `ALL_PROXY` / `TELEGRAM_PROXY_URL`, для Telegram HTTPX потребуется дополнительная установка:

```bash
python -m pip install "python-telegram-bot[socks]==22.5"
```

Это не добавляет SOCKS-поддержку `aiohttp` для внешних API: там нужен подходящий HTTP-прокси или отдельный SOCKS-коннектор. В учебной конфигурации такой коннектор не используется. Изоляция служебного SOCKS-прокси в unit-тесте не означает, что SOCKS проверен в рабочем окружении.

Документация PythonAnywhere: https://help.pythonanywhere.com/pages/403ForbiddenError/ и https://help.pythonanywhere.com/pages/AlwaysOnTasks/.
